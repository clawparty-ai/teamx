## 1. D13 里程碑切分 = **两步走**

| 步骤 | 内容 | 验收 |
|---|---|---|
| **第一步** | **只容器化 member**：新增 `provider=k8e`，member 以 Pod 形态直连**现有 server**（server 不动） | **现有 E2E 原样跑一遍 `provider=k8e`**（invite→provision→join→workspace 上报→destroy）+ 跨租户负例 + 拔节点演练 |
| **第二步** | **每租户一 server**（容器 + SQLite/PVC + 独立 CA）+ namespace 三元组 1:1:1 + 平台控制台 | 租户创建/回收全链 + CA 轮换/吊销 + 灾备恢复（含 CA） |

理由：第一步不引入 server 侧新变量、可回退（006 的 EC2 链已真机验证）；第二步的变量（多租户/CA/namespace）单独里程碑收敛。

## 2. D7 爆炸半径与存储 = **AIO 基线 + 存储硬约束**

- **v1 基线**：单节点 all-in-one k8e（C2）。
- **硬约束**：
  1. member workspace 走**网络附着存储**或**显式快照策略** —— 把"节点死"从"数据丢失"降级为"停机可恢复"。
  2. 快照频率 / 保留期写进 NFR（见 `requirements/002` NFR-10）。
- **后置项**：节点池分层（按档位/租户）、≥2 worker + 滚动窗口 —— 触发条件 = 首个企业租户出现。

## 3. D11 存量迁移 = **不强制迁移（C 默认）+ A 可选工具**

- **默认 C**：双 provider 并存；EC2 存量成员留原地（现网 xiaods-ec2 正被 fs 隧道服务，不搬）。
- **A 进 v1，但仅用户显式触发**（`node migrate` 类入口），且**验收写死**：
  1. 文件清单一致；
  2. 抽查哈希一致；
  3. 隧道同名重注册（沿用 stale-forward 自愈结论）。
  缺任一条 = 迁移失败并回滚（避免"文件对但隧道对不上"的半吊子状态）。
- **B（快照转储 EBS→对象存储→PVC）**：记入后续选项，v1 不做（链条最长、每段都要钱要时间）。

## 4. D6 BYO 主机接入 = **join token + 出站假设**

- **接入方式**：**一次性 join token**（非 SSH 一键、非 cloud-init）。
- **硬判据（xiaods-mac 实测）**：BYO 主机多在 **NAT 后** —— 接入流程**只走「主机 → server」出站**（隧道/轮询）。
  任何假设"平台能直连用户主机"的方案（如 SSH 一键）在默认网络下**不成立**。
- **三条子约束**：
  1. **key 归属**：key 留用户侧；server **不得**持 BYO 主机 SSH 私钥（006 的 server 持钥只对"平台开的机器"成立）。
  2. **命名碰撞**：单元/资源命名**含成员短 id**（现网 `teamx-<user>-*` / `tx-expose-<user>-*` 在"同用户多 team 同机"时会撞；EC2 已是 6 单元/实例，BYO 两 team 即 12 单元同机）。
  3. **防重放**：token **一次性 + 短 TTL + 可吊销 + 绑定预期 member_id**；member 上报是自称制，可重放的 token 等于任意"肉机"可注册并上报虚假 workspace。**吊销必须留审计**（谁/何时/为何）。
