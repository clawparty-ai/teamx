# CONTEXT — 术语表（teamx 设计）

> 本文件是**团队术语的唯一权威解释**（glossary）。只放简短定义，**不放实现细节**。
> 由 grill 设计访谈在术语 settled 时即时更新（协议 §4.3）。

## 团队与租户

| 术语 | 定义 |
|---|---|
| **团队（team）** | 一个共享目标的协作单元（成员、角色、goal、任务、讨论、隧道）。 |
| **租户（tenant）** | 一个团队的**独立运行环境**：一个 team + 一个 k8s namespace + 一套**独立 CA**。当前约束：**一个租户恰好一个 team**。 |
| **租户归属（owner）** | 创建租户的平台用户（`tenant_owners.user_id`）；租户资源的记账与配额责任方。 |
| **平台用户（platform user）** | 在云控制台登录的"人"（密码或 GitHub 身份）。是**人的权威锚点**；成员（member）是其在某团队内的座位。 |

## 可见性与加入（本轮新增）

| 术语 | 定义 |
|---|---|
| **可见性（visibility）** | `public` / `private`。`public` = 该团队出现在**全部团队**名录中、可被非成员发现；`private` = 非成员**完全不可见**（含直链）。**默认 private**，仅 owner 可改。 |
| **join_policy** | `open_request` / `invite_only`。与可见性**正交**：`public` 只代表"能被发现"，**不代表"欢迎加入"**。**默认 `invite_only`**。 |
| **全部团队** | 云控制台的公开名录页：列出所有 `visibility=public` 且状态为 `forming/active` 的团队。列表数据源**不调用任何租户 server**。 |
| **我的团队** | 云控制台的自助区：登录用户自己创建的团队（下一个 grill 主题）。 |
| **申请加入** | 用户对 `join_policy=open_request` 的公开团队发起的加入请求；**owner 人工审批**；批准后由控制台交付**邀请函**，申请人自行导入成为成员。 |

## 我的团队（本轮新增）

| 术语 | 定义 |
|---|---|
| **我创建的团队** | 我作为**租户归属用户**（`tenant_owners.user_id`）的团队 —— 我对它负责（配额、资源、审批）。 |
| **我加入的团队** | 我以**成员**身份加入的团队（`team_join_requests(status=approved)`）—— 我持有座位与工作区，资源记在**owner** 名下。 |
| **工作区（member workspace）** | 一个成员席位对应的 **member Pod**（含 PVC 与邀请函 Secret）。状态以**实时 k8s 为准**，k8s 不可达时回落加入时的快照并标注。 |
| **离开团队** | 成员主动退出：**平台侧申请置 `left` + 租户侧座位置 `left` + 回收 member Pod**（PVC 默认保留 7 天）。见 ADR-0002。 |
| **Owner 邀请函（二级菜单）** | 「我的团队」下的取件页：列出我拥有的团队及其 owner 邀请函，供复制导入。 |

## 经济（TCoin）

| 术语 | 定义 |
|---|---|
| **TCoin** | teamx 代币，**租户在 teamx 内的货币**。v1 只用于**记账与展示**（不阻断操作、无支付入口）。 |
| **两级账本** | 币的记账分两侧：**平台库**记租户级余额/充值/发放（平台是唯一发行方）；**租户 server**记成员级消耗明细（来自 `activity`）。需**对账**。见 ADR-0003。 |
| **计价汇率** | **固定**：`1 TCoin = 0.001 USD`（1000 TCoin = 1 USD）；账本只存**整数 TCoin**。 |
| **消耗口径** | v1 **只算 LLM tokens**（`activity` tokens × `model_pricing` 单价 → USD → TCoin）；`activity` + `model_pricing` 是**唯一计量源**。 |
| **落账** | 实时落账，`ref = activity 行 id` 幂等去重；append-only 流水，余额 = SUM，错误用**反向分录**冲正。 |
| **配额 vs TCoin** | **双轨分工**：配额管"**能不能**"（结构性上限，如团队数），TCoin 管"**花了多少**"；v1 互不触发。 |

## 信用（credit）

| 术语 | 定义 |
|---|---|
| **TCoin** | teamx 代币，**租户在 teamx 内的货币**。经济模型已定稿（design/017 + ADR-0003）：两级账本、固定汇率、只记不拦。 |
| **credit** | **团队（租户）的信用**：对**履约行为**的评分。模型见 design/018 + ADR-0004。 |
| **派生评分** | credit **不是**独立记账，而是由既有台账事件与 TCoin 余额**重算**出的**视图**；**系统是唯一写者**，无人可手改（owner 亦然）。 |
| **credit 信号** | 正向：`doc.verified` 完成 / `done→verified` 转化 / 批准后成员实际入场 / 成员留存 / TCoin 无欠费；负向：`doc.rejected` / 申请被拒冷却 / **TCoin 欠费（余额为负）** / 长期 `blocked` 未处理。 |
| **分档** | credit 对外只暴露**分档徽章**（S/A/B/C/D）；**精确分 + 构成明细**只给成员/owner。 |
| **构成明细** | 每个事件对分数的贡献清单（可解释、可审计；v1 是"申诉"的替代）。 |
| **冷启动基线** | 新团队基线 **60 分（B）**；有效事件 < **5** 条时显示「**数据不足**」且不显示分数。 |
| **衰减窗口** | 评分取**滚动 90 天 + 线性时间衰减**（近期权重高）；全期累计仅作审计。 |
| **防刷** | 同一 `doc`/事件去重只计一次 + 窗口自然衰减 + 单团队单日正向计分封顶；拒绝类由 owner 决定。 |
| **credit 无后果** | v1 credit **只展示、不影响**排序/审批/配额（与 TCoin「只记不拦」同构）。 |

## 边界与安全

| 术语 | 定义 |
|---|---|
| **元数据边界（D10）** | 平台默认**仅见元数据**（成员/团队的存在与状态），不见正文（任务、讨论、文件内容）；封闭枚举 + fail-closed；读正文需授权式 break-glass 且留审计。 |
| **service 车道** | 平台以**租户 CA 签发的服务证书**（身份 `service:platform-console:*`）经 mTLS 调租户 server 的受限通道；方法**白名单 fail-closed**。 |
| **详情白名单** | 公开团队详情对非成员暴露的字段集：团队名 / 公开简介 / goal 标题+状态 / 成员数 / 创建时间。**不含**成员名单、`invite_token`、证书与 session 信息。 |
